旧版 Go 规则引擎的真实输出基线
================================

用途
----
本文件是 tests/ruleEngineTest.aardio 中全部期望值的来源，用于避免"凭空编造与旧版一致的结果"。

来源说明
--------
旧版 Wails 项目（本机旧版 Go 工程目录）未被修改、移动或删除任何文件。
生成方式是把旧版的 rename 包**只读复制**到系统临时目录后，用 go run 实际执行：

（注：本节原本记录为本机绝对路径与临时目录路径，发布前已泛化为通用描述；
下方「原始输出」的数据一字未改，仍可作为历史参考。）

  1. 复制（只读，源文件保持不变）
     旧版工程/backend/pkg/rename/engine.go
     旧版工程/backend/pkg/rename/rule.go
     旧版工程/backend/pkg/rename/rules/*.go
     ->  系统临时目录/rename-verify/pkg/rename/ 与 系统临时目录/rename-verify/pkg/rename/rules/

  2. 在系统临时目录/rename-verify 下新建 go.mod（module renameverify / go 1.20）
     并新建 main.go：按与 backend/app.go App.AddRule 完全一致的方式构造规则，
     再调用 rename.Engine.Preview(filenames, modTimes) 打印结果。
     （app.go 层的自定义目标分支按 App.PreviewRename 的逻辑单独模拟）

  3. 执行
     cd 系统临时目录/rename-verify
     go run .

  4. 输出格式
     CASE|用例编号|文件序号|原文件名|新文件名|changed|错误信息|[CUSTOM]
     其中 CUSTOM 标记该行走的是自定义目标分支。

执行环境
--------
go1.23.4 windows/amd64
TS=<下面首行的数值>，即用例使用的固定修改时间（2026-01-02 15:04:05，本地时区）
F6 / G4 两个用例不提供修改时间，旧版会退回 time.Now()，因此这两条结果随运行日期变化。

由基线可以直接读出的旧版行为要点
--------------------------------
1. A4：addPosition 传非法值 "middle" 时不报错，而是被 ParseAddPosition 回退成 prefix，
   得到 Xphoto.jpg。因此 add_text.go 里 "无效的添加位置" 这个错误分支经 app.go 永远不可达。
2. E4：start / step / digits 全部缺失时，三个文件都得到 "0"（start=0, step=0 -> 恒为 0）。
3. F5 vs F1：useFileTime=false 时结果仍是文件修改时间，说明该参数在预览阶段没有被真正使用。
   【后续修订 · 有意分歧】aardio 版已让 useFileTime 真正生效：
   useFileTime=true 用文件修改时间（未提供则退回当前时间），useFileTime=false 用当前时间。
   因此 tests/ruleEngineTest.aardio 的 F5 用例期望值已按新行为改为 photo_<当天日期>.jpg，
   不再与本基线逐字一致；F1-F4、F6-F8 与原基线一致。详见 lib/frename/_.aardio 头部分歧说明。
4. D1 / D2 / D9：upper、lower 会连同扩展名一起转换；first、title 不动扩展名。
5. D5：title 会把连续空白折叠成单个空格。
6. B5：replace 的 all 范围替换覆盖完整文件名，包含扩展名。
7. A9：".gitignore" 被整体当作扩展名，主干为空。
8. I2：自定义目标与文件名相同（但路径不同）时，changed 仍为 true，
   因为旧版比较的是 CustomTarget 完整路径与 file.Path。
